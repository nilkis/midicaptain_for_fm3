#+title: Readme

* Midi-Captain for FM3
Bidirectional firmware for the *Paint Audio MIDI Captain* + *Fractal Audio FM3*

/English | [[file:README.ko.org][한국어]]/

*Your MIDI Captain finally knows what your FM3 is doing.*

Bidirectional firmware for the Paint Audio MIDI Captain that keeps its LEDs and display
*in sync with the real state* of a Fractal FM3 — effect block on/off, channels, scenes,
preset/scene names, tempo and looper — using Fractal's SysEx protocol.
Change a scene on the FM3 and the pedal's LEDs follow. Toggle a block on the pedal and
the FM3 answers back. No more guessing which light means what.

** Purpose

*** Pain point
- The MIDI Captain is a one-way controller (CC/PC) — it cannot read the state of the device it controls.
- It can change presets, scenes and effect blocks, but it doesn't know the *current* state of each block, so the on/off LEDs drift out of sync.
- Example: switching from a Clean scene to an OD1 scene turns Drive1 on in the FM3, but the MIDI Captain's Drive1 switch still shows "off".

*** Solution
Use Fractal's SysEx protocol (supported by FM3/FM9 etc.) for *two-way communication*: poll the FM3 state and reflect it on the MIDI Captain's LEDs and display in real time.
- Effect block on/off and channel (X/Y etc.) sync
- Current scene number, preset/scene names, BPM
- Tap-tempo LED sync, tuner screen

*** Why not a programmable MIDI controller (e.g. Morningstar MC6 Pro)?
Programmable controllers can *send* arbitrary SysEx and can trigger an action when an exact incoming
message matches, so a limited sync is possible by hand — e.g. mapping each of the eight fixed
scene-change replies to a preset toggle. But they cannot:
- parse a variable-length reply byte by byte (the FM3 status dump is dozens of 3-byte packets in one message)
- poll on a timer (no "ask the FM3 every 150 ms" loop)
- extract text (preset/scene names) from a reply and show it on the display
Full effect-block / channel / name sync therefore needs a controller that runs its own code —
which is what this firmware gives the MIDI Captain (CircuitPython on RP2040).

** Installation
For the Paint Audio MIDI Captain (STD 10-switch model). See also [[https://github.com/nicola-lunghi/hiper-midicaptain][hiper-midicaptain]].

*** 0. MIDI cabling — bidirectional (2 cables required)
This firmware *queries the FM3 over SysEx and reads the replies*, so a single cable
(MIDI OUT → IN) like a normal controller will not work. Connect *two 5-pin MIDI cables*, both directions.

| MIDI Captain | Dir | FM3      | Purpose                                              |
|--------------+-----+----------+------------------------------------------------------|
| MIDI OUT     | →   | MIDI IN  | commands & queries (scene, effect, tap, polls …)      |
| MIDI IN      | ←   | MIDI OUT | state replies (effect states, names, BPM …)          |

- If the FM3's MIDI OUT port is set to *THRU* you will get no replies. Check the MIDI OUT mode in FM3 =SETUP > MIDI/Remote=.
- Symptom with only one cable: switches still control the FM3, but LEDs/display don't follow the FM3 and preset/scene names stay =---=.

*** 1. Enter USB update mode
In normal boot the USB drive is disabled (the internal filesystem is kept writable so the device can save =config.json= — see =boot.py=).

1. Connect the MIDI Captain to a computer via USB
2. Power on *while holding Switch 1 (top-left footswitch, GP1)*
3. A USB drive named =MIDICAPTAIN= appears

*** 2. Back up the stock firmware (once, mandatory)
Before installing, *copy the entire contents* of the =MIDICAPTAIN= drive to your computer.
- Especially =code.py=, =boot.py= and the =lib/= folder
- If anything goes wrong, copying the backup back restores the stock state

*** 3. Copy the project files
Copy the following from this repository to the root of the =MIDICAPTAIN= drive, *as-is (overwrite)*.

| File / folder | Purpose                                                        |
|---------------+----------------------------------------------------------------|
| =code.py=     | main firmware (bidirectional FM3 SysEx controller)             |
| =boot.py=     | boot-mode control (Switch 1 → USB drive)                        |
| =lib/=        | ready-to-use CircuitPython libraries — *copy the whole folder*  |

=lib/= contains the four libraries this firmware needs (=neopixel=, =adafruit_st7789=, =adafruit_midi=,
=adafruit_display_text=) as CircuitPython 7.x =.mpy= files (Adafruit, MIT).
It is recommended to delete the device's existing =lib/= and replace it with this one — leftover files
from other firmware (e.g. PySwitch) or corrupted =.mpy= files cause boot errors (=Corrupt .mpy file=).

Drive layout after copying:
#+begin_example
MIDICAPTAIN/
├── boot.py
├── code.py
└── lib/
    ├── neopixel.mpy
    ├── adafruit_st7789.mpy
    ├── adafruit_midi/
    └── adafruit_display_text/
#+end_example
(=config.json= is created automatically on first boot)

*** 4. Reboot
1. Safely eject the USB drive
2. Power off, then power on again (without holding any switch)
3. After the welcome screen and LED test the device runs in FM3-controller mode

*** 5. Changing settings
- *Press and hold the rotary wheel for 1 s+* to enter Edit Mode — assign functions (effect, scene, tap tempo, tuner …) and LED colors to each switch directly on the device
- Settings are saved to =config.json= on the device
- To modify the code, enter update mode again (step 1)

*** Troubleshooting
- Drive doesn't appear :: Make sure the USB cable supports data; retry powering on with Switch 1 held
- Restore stock :: Enter update mode and copy back all backed-up files
- Settings don't save / =config.json= never appears after a normal boot :: The device's FAT filesystem may be corrupted (typically after many file deletions or an unsafe eject). Reformat it from the device and reinstall: enter update mode, open the serial console (e.g. Mu editor), press Ctrl-C to get a REPL, run =import storage; storage.erase_filesystem()= — the device reformats and reboots as a blank =CIRCUITPY= drive — then copy =code.py=, =boot.py=, =lib/= again (step 3). Your custom config is lost, so back up =config.json= first if you can.
- Development / debugging :: Use the [[https://learn.adafruit.com/welcome-to-circuitpython/installing-mu-editor][Mu editor]] serial console (see also [[https://github.com/nicola-lunghi/hiper-midicaptain][hiper-midicaptain]]). Auto-reload is on by default, so saving =code.py= applies immediately (uncomment =supervisor.disable_autoreload()= in =boot.py= to disable)

** CircuitPython libs
The MIDI Captain CPU board runs CircuitPython 7.3.1.
All required libraries ship in this repository's =lib/= folder — no separate download needed.

If you want to swap in newer versions, use *only the 7.x mpy bundle*
([[https://github.com/adafruit/Adafruit_CircuitPython_Bundle/releases/download/20231003/adafruit-circuitpython-bundle-7.x-mpy-20231003.zip][adafruit-circuitpython-bundle-7.x-mpy-20231003.zip]]).
=.mpy= files from 8.x/9.x bundles use a different format and will not load on 7.3.1. License info: =lib/LICENSES.md=.

** Compatibility and tested scope
The only combination actually tested is *Fractal FM3 + Paint Audio MIDI Captain (10-switch STD)*.

*** Fractal devices
| Device     | Status       | Notes                                                                        |
|------------+--------------+------------------------------------------------------------------------------|
| FM3        | *tested*     | =FM3_MODEL_ID = 0x11= (default)                                                |
| FM9        | untested     | Same SysEx protocol (Axe-Fx III family), expected to work in principle. Model ID 0x12 |
| Axe-Fx III | untested     | As above. Model ID 0x10                                                      |

To use with FM9/Axe-Fx III, change =FM3_MODEL_ID= in code.py to the device's SysEx model ID.
Model IDs per [[https://wiki.fractalaudio.com/wiki/index.php?title=MIDI_SysEx][Fractal Audio Wiki — MIDI SysEx]]:

| Model ID | Device          |
|----------+-----------------|
| 0x00     | Axe-Fx Standard |
| 0x01     | Axe-Fx Ultra    |
| 0x02     | MFC-101         |
| 0x03     | Axe-Fx II       |
| 0x04     | MFC-101 mk3     |
| 0x05     | FX8             |
| 0x06     | Axe-Fx II XL    |
| 0x07     | Axe-Fx II XL+   |
| 0x08     | AX8             |
| 0x0A     | FX8 mk2         |
| 0x10     | Axe-Fx III      |
| 0x11     | FM3             |
| 0x12     | FM9             |
| 0x14     | VP4             |
| 0x15     | AM4             |

(Axe-Fx II and older use a different SysEx command set and are not compatible with this project.)
